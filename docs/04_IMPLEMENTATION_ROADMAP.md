## 1. 実装ロードマップ概要

MVP開発を **10のフェーズ** に分けて実装します。

各フェーズは順序に従って進行します（前のフェーズが完了してから次に進む）

| フェーズ | 名称 | 実装内容 | 期間目安 |
| --- | --- | --- | --- |
| **フェーズ1** | 環境構築 | Vercel, Supabase, GitHub セットアップ | 1～2日 |
| **フェーズ2** | DB実装 | Supabase にテーブル作成 | 1～2日 |
| **フェーズ3** | API実装（認証・モヤモヤ） | ログイン、モヤモヤCRUD API | 3～5日 |
| **フェーズ4** | API実装（やりたいこと・パス） | やりたいこと、ステップ CRUD API | 4～6日 |
| **フェーズ5** | フロントエンド（ホーム画面） | 基本レイアウト、タブ実装 | 2～3日 |
| **フェーズ6** | フロントエンド（モヤモヤ機能） | モヤモヤ作成、修正、削除UI | 3～5日 |
| **フェーズ7** | フロントエンド（やりたいこと機能） | やりたいこと CRUD、パス表示UI | 5～7日 |
| **フェーズ8** | フロントエンド（アーカイブ機能） | アーカイブ表示、詳細表示、削除UI | 2～3日 |
| **フェーズ9** | 統合テスト・バグ修正 | 全機能の動作確認、ログ記録確認 | 3～5日 |
| **フェーズ10** | ローカルβテスト・Vercel デプロイ | 友人周りでテスト、本番環境へ | 2～3日 |

**総期間目安：26～41日**（期限なし、のんびり進行で OK）

### **4.2 Cold Start 対策**

Vercel サーバーレス関数の起動遅延に対応：
- **方法1：** UptimeRobot や Cloudflare Workers で定期実行（推奨）
- **方法2：** フロントエンド側でローカルキャッシュを活用

フェーズ3で実装予定

### **4.3 エラーハンドリング**

全API に try-catch を配置し、Supabase logs テーブルに自動記録：

```javascript
// API 実装時の標準テンプレート
try {
  // ビジネスロジック
  return { success: true, data: result };
} catch (error) {
  // ログに記録
  await supabase
    .from('logs')
    .insert({
      error_message: error.message,
      stack_trace: error.stack,
      endpoint: req.url,
      timestamp: new Date(),
    });
  
  return { success: false, message: 'エラーが発生しました' };
}
```
