## 1. API 概要

APIとは、**フロントエンド（ユーザーが見ている画面）がサーバーと通信するためのルール**です。

以下、各操作（ユーザーがボタンを押したり、画面を開いたりする時）で、どのような情報がやり取りされるかを定義しています。

---

## 2. 認証関連 API

### 2.1 ユーザー登録

**操作：** ユーザーが「新規登録」をする

**やり取り：**
```
ユーザーが入力 → サーバーに送信
  - メールアドレス
  - パスワード
  - ユーザーネーム

サーバーから返答
  - 登録成功 or 失敗
  - （成功時）ユーザーID
```

---

### 2.2 ログイン

**操作：** ユーザーが「メールアドレスとパスワード」でログイン

**やり取り：**
```
ユーザーが入力 → サーバーに送信
  - メールアドレス
  - パスワード

サーバーから返答
  - ログイン成功 or 失敗
  - （成功時）認証トークン（以後の通信で使用）
```

---

### 2.3 ユーザー情報取得 ⭐（質問1で必要と確認）

**操作：** ログイン後、画面上に「ユーザーネーム」を表示

**やり取り：**
```
画面が → サーバーに「ユーザー情報をください」と要求

サーバーから返答
  - ユーザーネーム
  - メールアドレス
  - 作成日時
```

---

### 2.4 ログアウト

**操作：** ユーザーが「ログアウト」をする

**やり取り：**
```
画面が → サーバーに「ログアウトします」と通知

サーバーから返答
  - ログアウト成功
  - （トークン無効化）
```

---

### 2.5 パスワードリセット

**操作：** ユーザーが「パスワードを忘れた」場合

**やり取り：**
```
ユーザーが入力 → サーバーに送信
  - メールアドレス

サーバーから返答
  - パスワードリセットメール送信成功
  - （ユーザーがメール内のリンクをクリック → 新パスワード設定）
```

## 3. モヤモヤ関連 API

### 3.1 モヤモヤ作成

**操作：** ユーザーが「悩みを書く」

**やり取り：**
```
ユーザーが入力 → サーバーに送信
  - テキスト内容
  - タグ（「悩み」「アイデア」「疑問」）

サーバーから返答
  - 保存成功
  - モヤモヤID
  - 作成日時
```

---

### 3.2 モヤモヤ一覧取得

**操作：** ホーム画面を開いて、モヤモヤ一覧を表示

**やり取り：**
```
画面が → サーバーに「モヤモヤの一覧をください」と要求

サーバーから返答
  - モヤモヤID, テキスト, タグ, 作成日時
  - （複数件のモヤモヤ）
  - ※アーカイブ済みは除外
```

---

### 3.3 モヤモヤ修正 ⭐（質問3で必要と確認）

**操作：** ユーザーが「モヤモヤのテキストを修正」する

**やり取り：**
```
ユーザーが修正 → サーバーに送信
  - モヤモヤID
  - 修正後のテキスト

サーバーから返答
  - 修正成功
  - 更新日時
```

---

### 3.4 モヤモヤ削除（仮削除＝アーカイブ）

**操作：** ユーザーが「モヤモヤをアーカイブ」する

**やり取り：**
```
ユーザーが入力 → サーバーに送信
  - モヤモヤID
  - アーカイブ理由（「なぜモヤモヤが晴れたのか」）

サーバーから返答
  - アーカイブ成功
  - アーカイブ日時
```

---

### 3.5 アーカイブ済みモヤモヤの完全削除

**操作：** アーカイブ画面で「削除」を押す

**やり取り：**
```
ユーザーが確認 → サーバーに送信
  - モヤモヤID
  - 削除確認（「本当に削除しますか？」の確認）

サーバーから返答
  - 削除成功
```

## 4. やりたいこと（タスク）関連 API

### 4.1 やりたいこと作成

**操作：** ユーザーが「やりたいことを新規作成」する

**やり取り：**
```
ユーザーが入力 → サーバーに送信
  - タイトル
  - 説明（任意）
  - 期限タイプ（明確な日付 or スケール）
  - 期限日付（明確な日付の場合のみ）
  - 重み付け（1～5）
  - やる理由
  - パス（ステップリスト）
  - 紐づくモヤモヤID（任意）

サーバーから返答
  - 保存成功
  - やることID
  - 作成日時
```

---

### 4.2 やりたいこと一覧取得

**操作：** ホーム画面を開いて、やりたいこと一覧を表示

**やり取り：**
```
画面が → サーバーに「やりたいことの一覧をください」と要求

サーバーから返答
  - やることID, タイトル, 期限, 重み付け, 進捗度
  - （複数件のやりたいこと）
  - ※アーカイブ済みは除外
```

---

### 4.3 やりたいこと詳細取得

**操作：** やりたいこと一覧から1つをタップして、詳細画面を開く

**やり取り：**
```
画面が → サーバーに「このやりたいことの詳細をください」と要求
  - やることID

サーバーから返答
  - タイトル, 説明, 期限, 重み付け, やる理由
  - ステップリスト（全ステップの状態）
  - 紐づくモヤモヤ情報
  - 期限超過状態（超過中 or 未超過）
```

---

### 4.4 やりたいこと修正

**操作：** ユーザーが「やりたいことの内容を修正」する（アーカイブ前）

**やり取り：**
```
ユーザーが修正 → サーバーに送信
  - やることID
  - 修正内容（タイトル、期限、重み付け、やる理由など）

サーバーから返答
  - 修正成功
  - 更新日時
```

---

### 4.5 やりたいこと削除（削除前に理由を聞く）

**操作：** ユーザーが「やりたいことを削除」しようとする

**フロー：**
```
【重み付けが4未満の場合】
  → 確認なしで削除可能

【重み付けが4以上の場合】
  → 「このやることをやらない理由を教えてください」と表示
  → ユーザーが理由を入力
  → 理由を記録してから削除
```

**やり取り：**
```
ユーザーが入力 → サーバーに送信
  - やることID
  - 削除理由（重み4以上の場合のみ）

サーバーから返答
  - 削除成功
```

---

### 4.6 やりたいこと完了

**操作：** ユーザーが「全ステップをチェック」して「完了」ボタンを長押し

**やり取り：**
```
ユーザーが操作 → サーバーに送信
  - やることID
  - 完了時の感想（任意）

サーバーから返答
  - 完了成功
  - 完了日時
  - 自動アーカイブ実行
```

---

### 4.7 感想記述（アーカイブ後の追記）

**操作：** アーカイブ後に「感想を追記」する

**やり取り：**
```
ユーザーが入力 → サーバーに送信
  - やることID
  - 感想テキスト

サーバーから返答
  - 記録成功
  - 更新日時
```

## 7. モヤモヤ・やりたいこと関連 API

### 7.1 モヤモヤ・やりたいこと紐づけ

**操作：** やりたいことを作成時に「モヤモヤを選択」して紐づける

**やり取り：**
```
ユーザーが選択 → サーバーに送信
  - やることID
  - モヤモヤID

サーバーから返答
  - 紐づけ成功
```

---

### 7.2 モヤモヤ解消確認 ⭐（質問4で必要と確認）

**操作：** 「このモヤモヤに紐づいた全やることが完了」した時点で、ユーザーに確認

**フロー：**
```
【やること完了時】
  → サーバーが「このやることに紐づくモヤモヤの全やることが完了したか」を判定
  → 全完了の場合、ユーザーに確認画面を表示
  → 「モヤモヤ『貯金をしたい』は解消されましたか？」
```

**やり取り：**
```
ユーザーが選択 → サーバーに送信
  - モヤモヤID
  - 解消フラグ（「解消された」or「未解消」）

サーバーから返答
  - 記録成功
  - 【解消の場合】モヤモヤもアーカイブ
  - 【未解消の場合】やりたいことのみアーカイブ、モヤモヤは残存
```

---

### 7.3 モヤモヤの未完了やること取得 ⭐（質問6で必要と確認）

**操作：** 1つのやることが完了した時、「このモヤモヤにはまだ未完了のやることがあります」と表示

**やり取り：**
```
やること完了時 → サーバーに「このモヤモヤに紐づいている未完了やることを教えてください」と要求
  - モヤモヤID

サーバーから返答
  - 未完了やることの数
  - （0件 → 全完了 → 解消確認へ進む）
  - （1件以上 → まだ未完了 → 「まだやることがあります！」と表示）
```

## 11. API エラーレスポンス

全API共通で、エラー時には以下の形式でサーバーから返答されます：

```
エラーが発生した場合
  - エラーコード（例：400, 401, 500など）
  - エラーメッセージ（日本語でユーザーに表示する内容）
```

例：
```
ログイン失敗時
  → 「メールアドレスまたはパスワードが正しくありません」

重み付け4以上を削除しようとした時
  → 「やらない理由を記述してください」
```

## 12. MVP実装での注意点

### 12.1 Cold Start対策

Vercel サーバーレス関数の起動遅延に対応するため：
- APIを定期的に叩く自動実行処理（Wake-up）を別途実装
- または、フロントエンド側でローカルキャッシュを活用

### 12.2 エラーハンドリング

全APIエンドポイントに try-catch を配置し、エラーログを記録：
- エラーは Supabase logs テーブルに自動記録
- ユーザーには分かりやすいメッセージを表示

### 12.3 リアルタイム同期

MVP段階では「ページ再読込」で対応。将来的にリアルタイムリッスン機能を追加可能。
